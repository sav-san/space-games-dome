# Купол — агент v10: телеметрия, RAG, диагностика и управление

Python-приложение с табличным GUI. Получает телеметрию Купола по WebSocket, классифицирует отклонения, предлагает проверки и решения через DeepSeek и базу из 1206 чанков. Команды пользователя из чата исполняются после подтверждения плана. Ограниченный автономный режим описан ниже и в docs/AUTONOMY_v09.md.

## Предложения решений v10

В GUI агент сам замечает активные отклонения и готовит решение без вашего сообщения в чат.
Появляется объяснение, гипотеза причины, ожидаемый эффект и проверяемый план. Вкладка чата открывается при новом плане.
Нажмите «Подтвердить показанный план» или «Отменить». Без подтверждения этот план не исполняется.
Срок — 120 секунд; изменение набора признаков/сессии аннулирует предложение. Перед каждым шагом повторно проверяются права и состояние.
При отсутствии доступной команды остаются инструкции по проверке для оператора. При недоступном DeepSeek показываются локальные рекомендации.

Настройка `AGENT_PROPOSALS=true` включает предложения (по умолчанию). Анализ предложения запускается не чаще раза в минуту;
одна и та же ситуация не предлагается повторно чаще раза в 10 минут. Ваш запрос и уже подготовленный план имеют приоритет.
При запуске `main.py` без GUI подтверждаемые планы не создаются; диагностика и автономность v09 работают по настройкам.

`AGENT_AUTONOMY` и `AGENT_PROPOSALS` независимы. Допущенные автономные действия v09 всё ещё могут выполняться без подтверждения.
Чтобы **все действия требовали вашего согласия**, задайте `AGENT_AUTONOMY=false`, `AGENT_PROPOSALS=true`.

Логи приведены к разделу 5 документа 03. Проверка: `python tools/check_logs.py logs`.
Документ 03, раздел 1, запрещает подтверждения человеком во время смены. Соответствие формату логов не означает соответствия этому требованию: режим с GUI-подтверждениями требует отдельного согласования с организаторами.
Подробнее — `docs/PROPOSALS_AND_LOGS_v10.md`.

## Автономность v09

По умолчанию `AGENT_AUTONOMY=true`: автоматические действия включены в GUI и при запуске main.py.
Для выключения укажите `AGENT_AUTONOMY=false` в `.env` или снимите галочку на вкладке чата.
В текущую автономную политику входят только:

- включение исправного выключенного охлаждения при работающем станке;
- включение исправной выключенной вытяжки при работающем ЧПУ;
- увеличение скорости уже работающей приточной вентиляции на 10 процентных пунктов при согласованном повышенном CO₂.

Перед действием: стабильные условия минимум 15 секунд на разных снимках, свежие каналы безопасности,
отсутствие опасностей/противоречий, актуальные права API, применимое обоснование из RAG и строгий ответ DeepSeek с оценкой ≥0.95.
Оценка модели не является измеренной вероятностью правильности. Количество логов само по себе не повышает её достоверность.
Автономный план не берётся из частично восстановленной диагностики. Станки самостоятельно не запускаются;
питание, защиты, двери и команды остановки не входят в автономную политику.

Отчёты о решении и результате видны в чате, консоли и `logs/agent_*.jsonl` (`observation` с `event=autonomy_report`, `decision`, `verification`).
Файл `state/autonomy.json` сохраняет результат и блокировку после неопределённой попытки. Подтверждение команды не доказывает устранение причины.
После неподтверждённого результата сначала проверьте оборудование. Для повторного разрешения автономности закройте программу,
сохраните `state/autonomy.json` для разбора, затем удалите этот файл и перезапустите. Переключатель GUI сам блокировку не сбрасывает.
Успешное действие повторно допускается только после исчезновения условия на 60 секунд свежих наблюдений и его нового появления.

Без ключа DeepSeek мониторинг и локальные правила продолжают работать; автономных действий нет.
Кнопка отмены плана также блокирует новые автономные попытки через общий сигнал отмены до следующего подтверждённого ручного плана или перезапуска.
Исполнение ручного плана и автоматического действия сериализовано. Подготовленный ручной план и таймер имеют приоритет.
Если выключить автономность после отправки команды, эта команда уже могла быть принята сервером.

Документ `docs/AUTONOMY_v09.md` описывает анализ версии друга, ограничения и проверки.

## Обновление существующей установки

Закройте GUI, замените файлы проекта, сохранив свой `.env` и `.venv`. Запустите `gui.py`. Новых pip-зависимостей нет. Старое `AGENT_LLM_MAX_CALLS=90` можно удалить: в v08 эта настройка игнорируется, даже если осталась в `.env`.

## Запуск с нуля в Windows / PowerShell

Распакуйте архив, откройте PowerShell в папке `dome_agent`, рядом с `gui.py`. Нужен Python 3.10–3.13 с Tcl/Tk.

Создание окружения:
```powershell
python -m venv .venv
```
Установка зависимостей:
```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```
Настройки:
```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```
Заполните свои адрес и ключи:
```dotenv
DOME_URL=ВАШ_IP
DOME_KEY=ВАШ_КЛЮЧ_КУПОЛА
DEEPSEEK_API_KEY=ВАШ_КЛЮЧ_DEEPSEEK
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash
AGENT_LLM_TIMEOUT=60
```
Сохраните и запустите:
```powershell
.\.venv\Scripts\python.exe gui.py
```
При следующих запусках нужна только последняя команда. `main.py` одновременно с GUI не запускайте: GUI сам открывает одну сессию агента. Для запуска без GUI можно использовать `python main.py`; настройка AGENT_AUTONOMY действует и здесь. На Linux/macOS путь Python окружения — `.venv/bin/python`.

Компьютер должен иметь доступ к серверу Купола и интернету для DeepSeek. Для смены IP измените DOME_URL и перезапустите приложение. Поддерживаются ws:// и wss://. Переменные окружения имеют приоритет над `.env`; если в PowerShell остался старый адрес, выполните `Remove-Item Env:DOME_URL -ErrorAction SilentlyContinue`. Не копируйте шаблон поверх заполненного `.env`.

## Интерфейс

- «Все показатели»: группы узлов и две таблицы. Выберите строку сверху — снизу все поля узла. Название вида `battery_01 (Аккумулятор)`, русское имя берётся из каталога сервера, при его отсутствии — из словаря. Неизвестные поля сохраняются.
- Группы: датчики, освещение, принтеры и ЧПУ, энергетика, климат, вода, безопасность, связь и прочее. Линии освещения определяются по актуальным именам щитка, не по зафиксированным номерам.
- Названия и строки проблемных узлов: critical/high — красный, medium — оранжевый, low — жёлтый. При устаревании данных актуальность снимается.
- «Отклонения»: факты, гипотезы причин, проверки, предлагаемые действия и ссылки на RAG. Причины остаются гипотезами.
- «Возможности API»: свежий каталог принтера/ЧПУ и отдельное указание, доступны ли pause/abort.
- «Чат и управление»: вопросы по текущему состоянию и подготовка планов.

## DeepSeek: исправление ложных сообщений о лимитах

В v08 удалены общий локальный предел 90 обращений и искусственные паузы после успешных/неуспешных ответов. Чат и диагностика имеют отдельные каналы выполнения: фоновый запрос не блокирует запрос чата. Новый фоновый анализ не запускается, пока активен запрос чата. Одновременно возможны один запрос чата и один запрос диагностики; сообщения чата обрабатываются последовательно, ожидая ответа, а не отклоняются из-за занятости.

Автодиагностика запускается по AGENT_ANALYSIS_INTERVAL (по умолчанию 60 с), при новых отклонениях — раньше, но не чаще раза в 15 с. Это частота фонового анализа, она не ограничивает чат. Старый AGENT_LLM_MAX_CALLS игнорируется. После ошибки нет локального cooldown и нет автоматического повтора того же LLM-запроса. Следующий запрос пользователя можно отправить сразу.

Ошибки показываются отдельно: HTTP 401 — ключ, 402 — сообщение API о балансе/оплате, 403 — доступ, 404 — endpoint/модель, 429 — реальное ограничение сервера (показывается Retry-After, если сервер его передал), 5xx — ошибка API. Таймаут, сетевая ошибка, неверный JSON и обрезка по max_tokens не называются исчерпанным лимитом запросов. HTTP-детали очищаются от ключей. AGENT_LLM_TIMEOUT задаёт сетевой таймаут; по умолчанию 60 с. При сохранении старого `.env` с 30 с используется именно 30 с — при медленных ответах измените на 60.

Модель отправляется как deepseek-v4-flash; в логах записывается также возвращённое API имя модели. Локальный поиск не вызывает других облачных моделей. Количество обращений теперь не ограничено клиентом; диагностический интервал остаётся настройкой частоты запросов.

## Управление во время производства

Общая блокировка «любой станок работает — нельзя переключать ничего» удалена. Проверяется конкретный адресат и его зависимости:

- Обычное освещение и независимые устройства доступны при работающем ЧПУ/принтере.
- Отдельную линию свободного принтера можно отключить при работающем ЧПУ, если по свежим данным нагрев выключен.
- Питание работающего станка и связанные охлаждение/вытяжку нельзя отключать до подтверждённой остановки. Для неизвестной линии нужно уточнить назначение: программа не угадывает его по номеру.
- Сработавшая защита конкретной линии блокирует её включение. Она не закрывает управление всеми остальными линиями.
- Частота WebSocket-запросов ограничена 0,3 с между отправками согласно условиям Купола. Это отдельный API, не ограничение DeepSeek.
- Защита от дребезга считается отдельно для каждой линии: не больше трёх отправленных переключений одной линии за 120 с. Переключения разных линий не расходуют общий счётчик. Реальные блокировки сервера также проверяются.

## Ручные планы и остановка станков

Примеры: «Отключи обычный свет», «Выключи свободный принтер», «Выключи обычный свет и включи аварийный», «Поставь ЧПУ на паузу».

Агент показывает план до восьми действий с точными node_id, action, value и задержкой. Проверьте план и нажмите «Подтвердить показанный план». План действует 120 с. Каждый шаг заново проверяет актуальные права, телеметрию и зависимости. Следующий шаг начинается после подтверждения предыдущего по свежим данным; при отказе/неизвестном результате остальные отменяются. Уже выполненные шаги автоматически не откатываются.

Поддерживаются turn_on/turn_off, line_on/line_off, home, start_job, resume, move, set_zero, set_speed, а также **pause/abort только когда они явно перечислены в controls данного узла в текущем describe_nodes**. Права перечитываются перед планированием и каждым исполняемым шагом. Если сервер не предоставляет pause/abort, программа не может добавить эти права: остановку выполняет оператор или организатор меняет права API. Предоставленный 01_API.md описывает режим, где пауза/отмена агенту недоступны, но текущий каталог имеет приоритет. Обесточивание работающего станка не подменяет штатную остановку задания.

Если сервер разрешает abort, можно подготовить последовательность «отмени задание ЧПУ, затем выключи его линию». После abort программа ждёт нового состояния и перед снятием питания проверяет, что станок остановлен и шпиндель не вращается. Pause означает удержание задания: после одной паузы питание не отключается.

Физические операции Оператора, загрузка/удаление файлов, probe_z, произвольный G-code, изменение доверия датчиков и сбросы защит не добавлялись в исполнитель. Для перемещения нужны оси, режим и скорость; для запуска — существующий файл, homed и свободный стол принтера. Эти проверки не заменяют осмотр заготовки и инструмента перед подтверждением.

Таймер до 24 часов задаётся от момента подтверждения, одинаковый для всего плана. Нужна работающая программа; при изменении сессии/роли, закрытии или перезапуске таймер отменяется. Условия «после завершения печати» не поддерживаются. «Отменить план / оставшиеся шаги» прекращает будущие шаги и ожидание проверки, но не отменяет команду, уже принятую оборудованием.

## База знаний и диагностика

В knowledge/chunks.jsonl — 1206 чанков, в том числе 20 разобранных типов инцидентов по логам 12–18 октября. Источники и ссылки — knowledge/log_manifest.json и source_refs каждого чанка. Отчёт — docs/RAG_UPDATE_v07.md. Поиск локальный BM25 с расширением токенов, подбором свидетельств и запросами по нескольким отклонениям. Чанки предоставляются модели как данные, а не инструкции. Правила не обучаются автоматически на советах оператора.

Отслеживаются ошибки, защиты, качество/свежесть данных, расхождения датчиков, рост CRC и утечки, новые обрывы связи и скачки SOC. История трендов до десяти минут очищается при разрыве более 90 с. Эвристические пороги не являются уставками оборудования. Порог устаревания узлов AGENT_STALE_SECONDS (20 с по умолчанию); допустимое опережение updated_at относительно оболочки снимка — до 2 с. Отказы управления показывают точные временные метки.

## Логи и проверки

Журналы UTF-8 JSONL в logs: run_id, seq, ts с часовым поясом, kind. Ключи скрываются, строки сбрасываются на диск. Команды и их ответы записываются как action, наблюдаемый результат — verification. Отсутствие ответа не считается доказательством невыполнения; автоматического повтора команды нет. Подробная диагностика — state/latest.json.

При обрыве WebSocket агент переподключается; в роли guest ждёт свою смену. Закрытие GUI завершает агента; уже начатый HTTPS-запрос может завершаться до таймаута.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

В v08 пройдены 74 теста: сценарий со скриншота, более 90 запросов, восстановление после ошибок, отдельные ошибки API, параллельный запрос чата, права остановки, последовательное выполнение и отмена плана. API DeepSeek и оборудование в среде разработки реально не вызывались; визуальная проверка на Windows не выполнялась.

Исторический прогон без сети: `python main.py --replay ПУТЬ_К_TELEMETRY.jsonl`. Пересборка базы при разработке: `python tools/build_log_knowledge.py`. Проверка исходников и исторических данных: `python tools/validate_log_knowledge.py`. Перед обычным запуском GUI эти команды не нужны.
