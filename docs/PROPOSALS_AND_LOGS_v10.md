# Предложения и журналирование v10

Основа — v09 из исправленной версии друга. Переработка дизайна GUI не включалась.

## Предложения

Новый Proposals отслеживает активные признаки и запрашивает у DeepSeek минимальный план исправления. Используется RAG и актуальный describe_nodes.
JSON проверяется строго; восстановление повреждённого ответа диагностики сюда не применяется. Проверяются ссылки на признаки/источники, параметры и доступность действий.
Предложения не запускают производство, home/move/set_zero. Запуск этих операций остаётся только по явному запросу в чате.
Неизвестные параметры, отказ guard или отсутствие прав оставляют только рекомендации, без исполняемого плана.
Для последовательности, в которой второй шаг пока запрещён (например, выключение питания после ещё не выполненной остановки), весь автоматически предложенный план отклоняется: нужны отдельные предложения по фактическому новому состоянию.

План публикуется с запросом разрешения и открывает вкладку чата. Сам Proposals не вызывает control.
Подтверждение действительно 120 секунд. При изменении признаков или сессии план аннулируется. Ручной запрос, отмена или исполненное действие во время LLM-анализа аннулируют его запоздалый результат.
Повторный запрос модели — не чаще минуты; одинаковый набор признаков — не чаще раза в 10 минут. Отмена не приводит к немедленному повторному предложению.
Без LLM — локальные рекомендации, без автоматического составления команды.

Для режима только с подтверждением: AGENT_AUTONOMY=false и AGENT_PROPOSALS=true.
При включённой автономности сохраняются три ограниченных типа самостоятельных действий v09. Уже подготовленные планы имеют приоритет.
Предложения с подтверждением реализованы для GUI. В консольном режиме не создаётся невидимый план на подтверждение.

## Раздел 5 документа 03

- UTF-8 JSONL, отдельный файл на запуск, последовательный seq, ISO-время с миллисекундами/часовым поясом, flush каждой записи.
- start в GUI и консоли: agent, version, models, config без секретов.
- observation: сводка и ключевые показатели АКБ, станков, климата, притока и охлаждения; полная телеметрия не дублируется каждые 2 секунды.
- dome_time: HH:MM из game_time.hour; неизвестное время не выдумывается, при смене сессии очищается.
- decision: situation, cause, confidence, evidence, plan, source из rules/llm/rag/mixed. Происхождение ручного подтверждения записывается отдельным origin.
- action: request, response.success/error и ref на decision, включая рутинные запросы и авторизацию (ключ скрыт).
- verification: ref именно на action, expected, observed, ok. Успех ответа сервера не подменяет подтверждение по новой телеметрии. Отказ, таймаут и отмена проверки также журналируются с ok=false и пояснением; неизвестный эффект не объявляется невыполнением.
- llm_call: model, purpose, prompt_tokens, completion_tokens, latency_ms, ok, error, summary. Если API не вернул usage или произошла ошибка, неизвестные токены записываются null, а не фиктивным нулём.
- message: входящие сообщения общего чата Купола сохраняются. Исходящих сообщений Оператору эта версия сама не отправляет; локальный GUI-чат не выдаётся за meeting_01.
- Отчёты автономности оформлены как observation с дополнительным event=autonomy_report. Решение и результат исполнения отдельно видны в decision/action/verification.

`python tools/check_logs.py logs` проверяет наличие полей, последовательность, ссылки decision→action→verification, source/confidence, токены и структуру ответа.
Незавершённый при аварийном убийстве процесса лог может содержать action без verification; валидатор укажет это. Программа не выдумывает проверку после смерти процесса.
Старые журналы не переписываются: проверяйте файлы новых запусков отдельно от старых версий.

## Ограничение регламента

Раздел 1 документа 03 прямо требует работы без окон и подтверждений. Запрошенный пользователем режим с подтверждением в GUI реализован, но не объявляется соответствующим этому разделу. Перед сменой его допустимость нужно согласовать. Соответствие разделу 5 касается структуры логов.

## Проверки

100 тестов пройдено, в том числе 9 новых: подготовка без исполнения, отмена запоздалого предложения, изменение ситуации, недостоверные ссылки, заблокированная команда, отсутствие LLM, цепочка журнала при успехе/отказе, поля вызова LLM и обнаружение неправильного ref. Проверка с реальным Куполом и реальным API DeepSeek не выполнялась.
