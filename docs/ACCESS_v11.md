# Управление замками v11 / 1.11.0

Причина прежнего отказа: локальный ALLOWED не включал set_lock, lock_door и unlock_door.
Документ 01_API.md разрешает эти команды агенту через control при наличии права в controls.
Исполнитель, подсказки чата и предложений, проверки телеметрии и журнал теперь поддерживают их.

Примеры в чате:

- «Открой дверцу 1 FabLab» — подготовить разблокировку замка 0.
- «Разблокируй дверцу 2 FabLab» — подготовить разблокировку замка 1.
- «Разблокируй обе дверцы бокса Фаблаб» — два последовательных шага.
- «Заблокируй дверцу 1 FabLab» — запереть уже физически закрытую дверцу.
- Для бокса Химлаб: set_lock с locked=true/false, общий замок.
- Для двери помещения: access_control_01 / unlock_door или lock_door / FABLAB, STORAGE, SERVER_ROOM, MAIN_AIRLOCK.

Первые четыре простые формы разбираются локально без DeepSeek. Сложные запросы и отложенные действия остаются в чате LLM.
Без номера агент уточняет одну из двух дверц; пользовательская нумерация 1–2 соответствует индексам API 0–1.
Вопросы, отрицания и просьбы выполнить действие позже не перехватываются локальным разбором.

Каждый план требует существующего подтверждения в GUI. Разблокировка не добавлена в автономную политику.
Права и условия проверяются при подготовке простой команды и повторно перед каждым исполнением.
Для FabLab требуется свежее состояние покоя принтера без заданного нагрева; webhook_state=COMPLETED не заменяет state.
Для запирания дверь должна быть CLOSED. Серверный lockdown, ошибки узла, устаревшие данные и отсутствие прав не обходятся.
После команды проверяется новый снимок locks/lock или doors[имя].locked. Одного success недостаточно.
Логи сохраняют цепочку decision → action → verification с expected, observed, ok.

## Что клиент изменить не может

По предоставленной спецификации дверь бокса физически открывает человек; снятие детали, чистка фильтра и другие operator_controls не являются правами control агента.
Новая версия управляет документированными замками и не имитирует физическое открытие, не меняет роль авторизации и не выдаёт операторские права.
Для выполнения самих физических операторских действий через API нужна серверная реализация и актуальная спецификация таких команд.
